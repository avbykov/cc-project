## Проект

Sea Radar — локальное веб-приложение для занятий по судовождению: карта пролива Дувр и суда на ней (демонстрационные, позже — настоящие из AISStream). Задание заказчика — `PROJECT_BRIEF.md`, задачи текущей недели с критериями приёмки — файл спринта (сейчас `SPRINT-01.md`, задачи B-01…B-07). Перед работой над задачей читай эти файлы, а не пересказ.

Документы сейчас лежат в корне репозитория; по плану курса они переезжают в `docs/tasks/`, записи checkpoint — в `docs/checkpoints/CHECKPOINT-0N.md` по шаблону `docs/checkpoints/TEMPLATE.md` (шаблона пока нет).

## Состояние

Кода ещё нет — репозиторий начинается с каркаса (B-01). Раздел «Команды» ниже — целевые команды из задания; уточни его по факту после создания `package.json`.

## Стек (зафиксирован в SPRINT-01)

Node.js 24, TypeScript 6.x `strict`, Next.js (App Router) + React, Leaflet 1.9.x, тайлы OpenStreetMap Standard с атрибуцией «© OpenStreetMap contributors», Playwright Test — единственный раннер тестов (один браузер). Другие библиотеки карт и тестовые фреймворки не добавлять; лишних зависимостей и примеров create-next-app не оставлять.

## Команды

- `npm run dev` — dev-сервер на `http://localhost:3000`, только loopback.
- `npx next build` — обязательная проверка после изменений карты (ловит SSR-ошибки Leaflet).
- `npx playwright test` — все тесты; один тест: `npx playwright test <файл> -g "<название>"`. Dev-сервер запускается из конфигурации Playwright. Установку браузера (`npx playwright install`) запускать в фоне — она долгая.

## Архитектурные правила

- **Leaflet только на клиенте** (он обращается к `window`): динамический импорт без SSR. Подключить CSS Leaflet; контейнер карты должен иметь высоту.
- **Одна конфигурация**: район (50.75° N, 0.95° E — 51.25° N, 1.95° E), начальный вид (51.00° N, 1.45° E, zoom 10), URL тайлов, `DEMO_TICK_MS = 2000`, маршруты демо-судов — каждое значение в одном месте.
- **Одна структура судна** для демо и настоящих данных: `id`, `name` (`string | null`, пустая строка → `null`), `lat`, `lon`, `speedKnots` (`number | null`), `courseDeg` (`[0, 360) | null`, курс движения), `timestamp` (ISO 8601 с зоной), `source` (`'demo' | 'aisstream'`). Ноль и `null` — разные вещи: `null` → «Нет данных», `0` → «0 уз».
- **Одно состояние судов**: карта и карточка читают из одного источника; один таймер на все суда, без накопления при перерисовках/hot reload, очищается при размонтировании.
- **Карточка**: форматы — литералами из SPRINT-01 (координаты `toFixed(5)`, скорость до десятых без хвостовых нулей + « уз», курс `Math.round % 360` + «°», время `HH:MM:SS UTC`). Название выводится как текст, никогда как HTML. Кнопки закрытия нет; повторный клик и клик по карте выбор не меняют.
- **Значок**: повёрнут по `courseDeg`, при `null` — нейтральный круг. Атрибуты `data-vessel-id` и `data-icon="course"|"neutral"` — тесты находят суда только по ним.
- В тестах запросы к тайлам блокируются.

## Границы

- Делать только задачи текущего спринта; не проектировать и не заготавливать будущее (сервер, кнопку загрузки, настоящие данные — пока их нет в текущем спринте).
- Ключ AISStream и прочие секреты не читать, не выводить, не коммитить (`.env*` в `.gitignore`).
- После задачи: показать diff и сопоставить с критериями задания; в checkpoint записывать только факты (команды и их результат, что проверено визуально, что осталось).
